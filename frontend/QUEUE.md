# 浏览器消息队列与运行引导

- 运行中发送 / Enter 默认排队，不停止当前任务；停止为独立按钮。中文输入法选词 Enter 不发送，Shift+Enter 换行。
- 输入框上方按会话显示 FIFO 队列，队列独立于聊天记录，不会提前进入模型 history。附件、解析预览及发送 options 在入队时快照，真正发送时通过现有发送流程读取最新消息 history。
- **引导**将该项发送给当前 pendingRequest 的 assistantMsgId。仅后端 Agent 运行支持；普通 CHAT / 特殊模式、初始化、收尾阶段可能返回 409。202 成功后才移除该项；失败在该项内显示、保留并暂停队列。请求处理中不可重复引导、编辑、撤回或自动消费该项。
- **编辑**先撤回队列项并恢复输入框文本、附件和 options，暂停队列；修改后需重新发送入队，再点击继续。**撤回**只移除队列项。
- assistant 下的“已收到”表示后端已接受；“已应用”表示进入后续模型调用上下文，不代表操作成功，也不撤销此前操作。202 和 SSE 按引导 ID 去重，“已应用”不会退回“已收到”。
- 仅成功完成当前任务才自动发送下一项。`runOutcome` 的 awaitingApproval / error / stopped、SSE 错误、停止与会话切换均暂停；审批保留 pendingRequest，走原有审批恢复入口。审批处理后仍需手动继续队列。无 runOutcome 的普通流仅在收到 `[DONE]` 且无错误时使用兼容完成判定，连接直接关闭不算成功。
- 队列仅保存在**当前浏览器的 localStorage**（`saki_chat_queues_v1`），不是后端权威队列；刷新恢复一律暂停。后台轮询恢复不凭运行消失认定成功，也不会自动续发，请确认记录并点击继续。切换会话不跨会话发送，旧流响应不会覆盖新会话。

## 限制

- 不提供跨设备 / 跨浏览器同步、多标签页调度互斥或恰好一次交付保证。避免多个标签同时执行同一队列。
- localStorage 空间有限，附件快照（尤其图片）可能超限；保存失败会显示提示，该页内仍可用，但刷新可能丢失未保存变更。
- 引导接口无幂等键；网络中断可能无法判断后端是否已接受。重试前核对已收到记录，避免重复引导。
- 自动队列发送只在当前页面且当前会话运行；离开会话后需显式恢复。后端决定 CHAT / Agent 路由，前端不额外调用模型判断可否引导。

## 无模型验证

在 frontend 目录执行 `node --test tests/chatQueue.test.mjs` 和 `npm run build`。纯工具测试覆盖 FIFO、快照、同步占用锁、会话隔离、恢复暂停、编辑撤回、引导失败保留、终态判定、引导去重 / 乱序与 IME。

全量测试可通过 `npm test`（`node --test tests/*.test.mjs`）执行，包含已有的 `turnNavigator.test.mjs`。`localize.js` 直接读取共享的 `i18next` 实例，并使用带 `.js` 扩展名的字典导入，避免 Node 测试加载浏览器语言检测和 IP 请求。新增的 `chatRuntime.test.mjs` 与 `localize.test.mjs` 覆盖加载 epoch、发送配置、迁移空值、缓存失败和动作预览清理。本次修改未执行终端测试，需由主代理统一验证。
