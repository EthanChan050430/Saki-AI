# EGAR：面向本地量化小模型 Agent 的证据门控动作修复

**研究类型：可复现探索性实验；非同行评审论文。日期：2026-11-12。**

## 摘要

小语言模型在工具调用中可能产生格式错误、未获取证据便填写参数、忽略状态依赖等问题。本研究为 Saki-AI 提出 EGAR（Evidence-Gated Action Repair）研究原型：将模型的动作建议与执行权限分离，用类型契约和可观测证据检查动作，并在有限推理预算内返回诊断进行修复。模型参数保持冻结，不调用外部大模型裁判。实验仅使用本机 Ollama 和无真实副作用的合成工具环境。完成 192 个 episode 后，Llama3.1 8B 的成功率由 15/24 提升到 21/24，增益全部来自缺失记录弃答，可回答任务保持 15/18；Gemma3 4B 在严格 JSON 接口下四条件均为 0/24。本研究未验证大模型等效性或通用能力提升，结果仅支持一个领域专用的弃答修复效应，并暴露出接口与任务混杂问题。

## 1 引言与研究问题

用户希望小模型 Agent 达到大模型效果，但“全参模型”不是一个严格的对照组：小模型也可以是稠密全参数模型；参数规模、量化精度与是否全参数微调是三个不同维度。因此本研究操作化为：在固定小模型权重下，推理时动作验证和反馈能否提高多步工具任务完成率？

RQ1：解析后结构校验与修复相对直接 JSON 提示有何影响？RQ2：加入证据检查与有界修复是否进一步改善任务成功？RQ3：改善是否只是更多推理预算造成？RQ4：无足够信息时，系统是否正确停止，而不是猜测参数？

大模型等效性需要单独验证。若没有实际的大模型对照、任务分布和预设等效界限，即使某组成功率达到 100%，也不能声称已达到大模型水平。

## 2 相关研究

ReAct [1] 将推理和环境行动交替执行。ReWOO [2] 将部分规划与观察分离，降低重复上下文成本；其中小模型能力迁移例子包含微调，不能直接支持纯推理时增强的结论。TinyAgent [3] 用专用工具数据微调小模型，并结合检索和量化，在特定 Mac 工具任务上与更大模型比较；其任务特定结论不能推广为通用等效。

CRITIC [4] 已提出通过外部工具反馈修复输出，Reflexion [5] 已提出无需更新参数的语言反馈机制。因此“调用工具后重试”并非本研究首创。Huang 等 [6] 区分内在自纠错和外部反馈，指出 oracle 正误标签与不公平采样预算会误导评估。本研究将隐藏评分逻辑与可部署的运行时检查分开。ToolSandbox [7] 强调状态依赖、信息不足和中间里程碑，启发本研究关注多步执行，而非仅判断单个 JSON 是否可解析。

**创新定位：** EGAR 是一个待检验的算法组合与实现，不声称已证明全球首创。进一步检索发现 RubricRefine [8] 已研究无需训练的执行前契约检查、参数来源检查和迭代修复，与本方案存在直接重叠。因此不能把“执行前检查＋修复”列为新算法贡献。本原型的可检验差异是：对实际逐步工具观察实施确定性的证据门控，而非对整段候选代码进行 rubric 评分；这一区别是否有价值，仍需直接基线实验。执行来源追踪综述 [9] 也表明证据关系与执行依赖已有系统研究。当前工作的定位应是本地小模型上的探索性研究原型，而非已经成立的原创算法突破。

## 3 方法

令用户目标为 g，工具契约集合为 T，真实观察历史为 H_t，模型提出动作 a_t。定义结构检查 S(a_t,T)、公开运行时前置条件 P(a_t,H_t,T)，以及针对须来自观察的参数的证据检查 E(a_t,H_t,g)。所有检查都禁止访问测试集目标答案和理想动作序列。

对于适用的可执行动作，接纳条件为 S ∧ P ∧ E。若不满足，执行器不调用该工具，而将公开可计算的错误诊断反馈给同一个小模型；达到重试或总调用预算后终止。ask、abstain、answer 等非工具行为必须有明确语义，不能因结构化输出要求而被迫选择工具。实验中的具体动作字段与停止条件以冻结协议为准。

### 算法 1：有界证据门控

```text
输入：目标 g，公开契约 T，最大动作步数 K，每步修复上限 R
H ← 初始公开上下文
对每个动作步骤（最多 K 步）：
    最多提出 R+1 个候选，每次消耗一次模型调用
    a ← 小模型(H, T, 上次公开诊断)
    按当前实验臂检查结构及适用的前置条件/证据
    若拒绝：记录并反馈；本步修复耗尽则停止
    若接纳且为终止动作：终止，不查询隐藏评分器
    若接纳且为读取动作：执行一次，追加真实观察，进入下一步
输出：轨迹与停止状态；由隔离评分器事后评分
```

类型合法不等于语义正确。观察中存在某个标识符，也不保证它属于用户所需对象；门控必须按部署契约定义，并将残余错误交给任务指标反映。不得把模型文本中的伪造 Observation 当成可信观察。

### 3.1 保证与代价

若所有派发入口均执行正确实现的检查，则被派发动作满足这些检查，这是执行器的程序不变量，不是任务正确性定理。模型仍可能选择错误工具、错误实体或过早结束。若单次有效提议概率为 p，独立提议的理想接纳概率为 1−(1−p)^B；真实修复样本相关，且有效不代表正确，因此不使用该公式替代实验结果。

代价包括额外模型请求、诊断上下文和验证器维护。必须报告实际调用数、生成 token、端到端时间以及冷启动影响；同样的最大预算不保证同样的实际算力。

## 4 实验与结果

### 4.1 冻结协议与实验范围

在 localhost:11434 的 Ollama 上完成 192/192 个 episode：Gemma3 4B 与 Llama3.1 8B 各运行 24 个任务、4 个条件，共 474 次模型请求。模型为本地 Q4_K_M 版本；运行时版本与模型 digest 保存在 environment.json。任务为合成服务目录查询，包含干扰记录、服务/区域匹配、读取字段与缺失记录；每组有 18 个可回答任务和 6 个缺失任务。随机实例而非任务家族被留出，没有标准公开 benchmark 或真实 Saki 工作流测试。

种子 731904，temperature=0，num_ctx=4096，num_predict=192，HTTP 超时 240 秒。每任务最多四个动作步骤；direct 不修复，其余条件每步骤至多一次修复，因此请求上限分别是 4 与 8，而不是可任意分配的总预算 B。条件顺序按任务轮转、模型分组运行。数据、协议、推理实现和测试的 SHA256 在调用前冻结，复核通过。HTTP 错误计失败，不自动网络重试。

四条件为 direct、schema、EGAR 和 generic_egar。最后一个与 EGAR 使用相同门控和预算，但修复提示不提供具体错误，是反馈消融，**不是无门控的等预算普通重试基线**。各条件均接收普通读取工具的真实错误。schema 仅使用提示、严格 JSON 解析、字段/类型校验和一次错误反馈重试。**所有实验臂均未传 Ollama format，未使用 JSON Schema 约束解码**，因此本实验没有回答服务端结构化输出能否解决接口问题。Gemma 的一个原始响应为带 ```json 围栏的 list 动作对象，整段无法通过 json.loads；这不是约束解码失效。

实际 EGAR 也检查终止行为：answer 必须引用成功读取的记录，该记录的服务与区域精确匹配目标，并逐字复制所需公开字段；abstain 必须在完成目录读取后确认不存在精确匹配。检查器不访问 private gold，但这种领域专用验证比通用参数来源检查强，不能无代价迁移到开放式自然语言推理。控制组以最终值评分，不额外要求引用正确。

### 4.3 失败分析与反证

**Llama 的全部增益来自缺失记录的正确弃答。** 四条件可回答任务均为 15/18；缺失任务成功数依次为 0/6、0/6、6/6、2/6。因此没有观察到可回答查询准确率提升，也不能声称一般推理能力提高。EGAR 仍有 3 个任务耗尽修复预算。数据生成中 port 字段只出现于缺失任务，字段身份与缺失性混杂，必须在后续独立实验中正交化。

**Gemma 在本接口上全部失败。** 严格解析要求响应恰为一个 JSON 对象，实际输出常带 Markdown 围栏；门控前的解析失败阻断了所有任务。这是接口兼容性负结果，不能解释为 Gemma 没有解决底层查询的能力。未在看到结果后改用宽松解析器并替换原实验；原始响应完整保留。需要另设版本明确的约束解码/解析器实验才能评估修复效果。

### 4.4 可复现性与验证

[复现入口](README.md)、[详细结果](results-detail.md)、[机器可读统计](detailed-aggregate.json) 和 [原始轨迹](results.jsonl) 保留在本目录。重新执行八项离线测试全部通过，覆盖数据泄漏边界、确定性、标识符/弃答门控、无拒绝动作执行、预算及普通错误反馈；冻结哈希校验与统计重算均通过。测试通过证明实现所测不变量，不证明任务分布外有效性。

## 4.5 结论

本探索性实验支持一个有限结论：在本合成查询环境中，领域专用的证据与终止行为门控配合具体诊断，改善了 Llama3.1 8B 对缺失信息的处理；没有改善可回答任务，也没有解决 Gemma 的输出接口问题。工作完成了算法原型、可审计实验与负结果分析，但**尚未实现或证明小模型达到大模型效果，亦未确立全新算法的原创性**。不得把本研究原型描述为已部署的 Saki 能力提升。

## 5 有效性威胁与边界

合成环境的任务覆盖、人工设计的验证器、少量任务、单次采样及本地硬件调度都会限制外推。即使参数数值是随机生成的，任务模板仍由研究者设计，不能视为独立真实世界基准。没有同一模型 F16 与 Q4 对照，不能隔离量化效应。没有大模型对照，不能估计与大模型的差距。没有生产系统集成，不能声称 Saki 的日常 Agent 已得到提升。

下一阶段应使用独立标准测试集，增加任务模板和随机种子，匹配模型/提示/实际成本，报告配对置信区间及失败分类，并事先给出等效检验界限。应把训练后的小模型、纯推理时增强以及大模型原生策略分别列为实验臂。
