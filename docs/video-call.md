# Saki 视频通话

## 当前行为

- 通话顶部模型菜单合并已启用提供商的模型目录，切换后终止旧回复，下一轮使用所选提供商和模型。
- 通话属于打开它的那个聊天：每轮对话完成即写入该聊天的历史记录（用户消息是 `content`，Saki 的回复是 `parts`），和普通聊天消息格式一致，可在侧边栏重新打开继续。通话中挂断、刷新或崩溃都不会丢掉已经说过的内容。
- 从某个聊天点开视频通话时，会带该聊天此前的完整对话（最多 500 条、每条 10 万字符、合计 100 万字符）进入上下文；模型先看到最近 12 条，较早内容以索引和相关摘录形式提供，并可通过回忆工具按 ID 分页取原文，所以"那个方案""刚才说的"这类指代可以接上。换一个聊天再点开，就是另一个聊天的上下文。
- 展示区的内容会作为上下文继续参与对话：请求里带上左右两侧组件的完整正文，以及展示/关闭/替换事件历史（最近 100 项），被替换或关闭的旧表格、旧幻灯片也能通过回忆工具取回，且不会被误当成当前内容。
- 通话里的工具调用会像普通 Agent 一样写进主聊天：网页搜索、查看摄像头、展示/收起内容、回忆资料都会显示为带状态的执行步骤，复杂 Agent 的其它工具同样会同步；完成、失败或被中断都会落到对应状态，挂断后仍保留在聊天记录里。
- 麦克风图标内用粉色填充实时显示输入音量，静音时清零，不显示启动或就绪文字。音量采样独立于语音识别，本机模型加载或浏览器后备识别期间也能工作。转写优先使用本机 Whisper；首次启动可等待约三分钟，失败后尝试浏览器识别，没有可用后备时显示重试提示。
- 全屏按钮对通话内容容器请求全屏，进入后变为退出按钮。退出全屏保留通话，挂断释放全屏和麦克风。
- 开启摄像头后，模型可以调用工具请求一张 JPEG。前端只在请求到达时采集，不持续传输视频；关闭摄像头或挂断会停止媒体轨道。视觉理解需要所选模型支持图像。
- 即时回复可以搜索网页、查看摄像头、展示或关闭组件。一次回复最多执行三次轻量搜索/视觉工具，复杂任务进入完整 Agent，已有资料会保留。
- Saki 自主判断是否展示相关内容，也可仅口头回答，并自行选择左侧、右侧或左右同时展示。展示区支持任意普通文字、Markdown（标题、列表、代码、链接等）、混合内容块，兼容选择、询问、表格、图片、幻灯片、文档及生成文件预览；口述说明可以不同于展示正文。默认新内容替换当前布局，显式保留另一侧时可只更新一侧。用户可单独关闭一侧，Agent 可关闭左侧、右侧或全部。
- 展示指令漏写 `[[SHOW]]` 时也能识别：整段回复若就是一个完整的展示 JSON，会直接渲染成面板，只播报其中的 `speech`，正文不会念出来、也不会出现在气泡里；工具步骤显示的是内容标题而不是原始 JSON。半截 JSON 或普通文字里的花括号仍按普通对白处理。
- 默认取景保留裙摆下方少量腿部。单侧展示时角色走到另一侧，两侧展示时站在中间；关闭后根据剩余内容调整位置，全部关闭后返回开板前的位置及缩放。走位包含左右腿交替屈膝、身体起伏和朝向变化，中途取消/重开保持位置连续。

## 本机转写依赖

仓库根目录执行：

```powershell
python -m venv .venv-video-call
.venv-video-call\Scripts\python.exe -m pip install -r backend/services/video-call-requirements.txt
```

可选后端环境变量：

- `SAKI_ASR_PYTHON`：指定 Python 可执行文件；默认优先使用仓库中的 `.venv-video-call`。
- `SAKI_ASR_DEVICE`：`auto`（默认）/`cuda`/`cpu`。`auto` 会先尝试 GPU，初始化失败才退回 CPU。
- `SAKI_ASR_MODEL`：强制两侧使用同一模型，覆盖下面的分设备默认值。
- `SAKI_ASR_GPU_MODEL`（默认 `small`）、`SAKI_ASR_CPU_MODEL`（默认 `base`）：分设备模型。GPU 上 `small` 比 CPU 上的 `base` 更快也更准。`turbo`/`large-v3`/`medium` 也可以选，但 Whisper 的编码器固定按 30 秒窗口计算，`turbo` 在本机实测约 650 ms/条（`small` 约 230 ms）而中英混合准确率没有提升，因此不作默认。
- `SAKI_ASR_GPU_COMPUTE_TYPE`（默认 `float16`）、`SAKI_ASR_CPU_COMPUTE_TYPE`（默认 `int8`）。
- `SAKI_ASR_THREADS`：CPU 解码线程数，默认 `min(8, CPU 数-1)`；超过 8 线程反而变慢。
- `SAKI_ASR_BEAM`：束搜索宽度，默认 1（最快）。
- `SAKI_ASR_LANGUAGE_MODE`：`auto`（默认）/`client`。`auto` 不锁定语种，让 Whisper 自己判断——中英混说时这是准确率的关键；`client` 则强制使用前端传来的界面语种（旧行为）。
- `SAKI_ASR_PROMPT`：覆盖解码提示词；设为空字符串可完全关闭提示词。
- `SAKI_ASR_HOTWORDS`：逗号分隔的热词，用于把领域词推向正确写法。默认 `雅思`。**热词必须精简**：实测加入过多常用词会显著拉低准确率（把 meeting 听成"讨论"、deploy 听成"复杂"），只放你确实常说、又总被听错的专有名词。
- `SAKI_ASR_REPLACE`：`错=对` 形式的同音词纠正，逗号分隔，默认 `亚斯=雅思,亚思=雅思`。热词负责声学上把词解码对，这一层兜住残留的同音误写。设为空字符串可关闭。
- `SAKI_ASR_VAD=1`：在 worker 侧再跑一遍 VAD。默认关闭，因为采集端已经做过断句，重复 VAD 会截掉词尾。
- `SAKI_ASR_OFFLINE=1`：只使用本机已缓存模型。

首次使用且没有缓存时需要下载模型。Docker 构建包含转写依赖，缓存位于数据卷的 `asr-cache`。

### 延迟与准确率取向

采集端 64 ms 一帧：2 帧有声即开始（前 320 ms 预录缓冲保证不丢字），6 帧静音结束，结束前裁掉多余的尾部静音再上传；判断结束用 0.78 倍阈值的迟滞，避免把句尾的轻声辅音切掉。

worker 侧按设备选模型、关闭时间戳、关闭重复 VAD，并使用**中英双语**的 `initial_prompt`。提示词刻意不写成中文单语：强制 `language=zh` 配中文提示词时，Whisper 会把英文词改写成中文谐音，甚至把整句英文直接翻译成中文；改成不锁定语种 + 双语提示词后这个问题消失。

静音或噪声时 Whisper 会复读提示词或输出 `[BLANK_AUDIO]`、`谢谢观看` 一类字幕残句，这些以及重复循环都会被过滤掉，不会当成用户说的话发给模型。中英切换处 Whisper 会插入多余逗号（`把这个，JSON 文件`），这些逗号会被删掉，中文短语之间的正常逗号保留。

前端还有一道回声过滤：只把覆盖 Saki 上一句 50% 以上（或长度 ≥10 字）的转写判为扬声器回声。早期实现只要用户的话是 Saki 句子的子串就丢弃，用户回一句"挺好的"会被吞掉。

### 语音播放的流式与流水线

回复文本一到就切句、切句就合成播放，不等整段生成完。切句规则（`frontend/src/utils/videoCallSpeech.js`）：

- 优先在句末标点（`。！？!?；;…` 换行）处切，连续的 `？！` 保持在一起。
- 首句格外短：只要出现第一个逗号级停顿（≥6 字）就先开口，因为**首句的长度直接决定沉默多久**。
- 之后的句子在标点附近按 72 字上限切；没有任何标点时按上限硬切，且不会把英文单词或数字从中间劈开。
- 小数点不当作句末（`1.0.3` 不会被切开）。

切出来的句子由 `createSpeechPipeline` 调度，**合成与播放是两条链**：第 N+1 句在合成的时候，第 N 句还在播。这是关键——如果像以前那样把"合成+播放"串在一条链上，每个句号后面都会空出一次完整合成的时间，听起来就是断断续续。

另外通话接通时就会预热语音引擎（`voice.warm()`），首句不必再等 TTS 的 worker/模型启动。

### 不读 emoji 和颜文字

聊天记录里 Saki 的表情符号原样保留（正文、历史、导出都还在），但**送去合成之前会被清掉**，不会念出"笑脸"或一串乱音。清理在 `toSpokenText()`（`frontend/src/utils/videoCallSpeech.js`），作用范围只有语音与字幕：

- emoji 字形、肤色修饰符、国旗、ZWJ 组合序列，以及残留的变体选择符和键帽符。
- 颜文字：括号内没有任何文字（字母、数字、汉字、假名）的符号串，如 `(￣▽￣)`、`(｡･ω･｡)ﾉ`。`（注）`、`(2024)`、`(ﾃｽﾄ)` 这类真实文本不受影响。
- 装饰性符号：方框绘制、几何图形、杂项符号、箭头、音符、勾叉。
- 经典 ASCII 表情：`:)`、`;P`、`^_^`。时间、比例和网址（`12:30`、`3:1`、`https://…`）不受影响。
- 标记：`[expression:…]`、markdown 强调符。

清理后如果整段只剩标点（比如模型只回了一个表情），这段不会被送进语音引擎，直接跳过。

### 领域词与同音词

Whisper 对同音词没有上下文时只能猜，`雅思` 常被写成 `亚斯`。这里用两层解决：

1. **热词**（`SAKI_ASR_HOTWORDS`）让解码器在声学上偏向目标写法。
2. **同音词纠正**（`SAKI_ASR_REPLACE`）把仍然漏出来的错写改回来，比如 `亚斯=雅思`。

热词不是越多越好，实测（5 条含"雅思"的语音 + 14 条中英混说样本）：

| 配置 | 领域词正确 | 混合集错误率 |
| --- | --- | --- |
| 无热词（原默认） | 2/6 | 6.5% |
| 热词=`雅思` | 5/6 | **4.9%** |
| 热词=`雅思，托福，Saki` | 5/6（且出现 "Yasco 是报名了吗" 的乱码） | 5.6% |
| 热词=`雅思` + 同音词纠正（现默认） | **6/6** | 4.9% |

所以默认只放一个词。要加自己的词，把词写进 `SAKI_ASR_HOTWORDS`，并把顽固的错写按 `错=对` 放进 `SAKI_ASR_REPLACE`。

### 实测

语音识别延迟（5 秒中文语音，16 核 CPU + RTX 3060）：CPU `base` 约 1.2 s、GPU `small` 约 0.36–0.49 s，且 GPU `small` 的转写内容明显更准。

中英混合准确率（14 条合成混说样本，按中文字+英文词计错误率）：

| 配置 | 错误率 |
| --- | --- |
| 旧：`client=zh` + 中文单语提示词 | 19.3%（纯英文句被翻译成中文，141.7%） |
| 新：`auto` + 双语提示词 | **6.5%**（纯英文句 0%） |

GPU 模式依赖 CUDA 版的 cuBLAS/cuDNN；缺少时 worker 会自动退回 CPU 而不是报错。想确认实际用的是哪条路径，看后端启动日志中的 `[VideoCall] 本机语音识别已就绪：<模型> on <设备>`，或请求 `/api/video-call/transcribe/ready` 查看返回的 `device`/`model`。
